Q1: User Persona Taxonomy, Goals & Feature Matrix

To eliminate paper-based documentation delays, reduce PPE waste, and prevent clinical bottlenecks, Version 1 identifies three primary roles:

User Role Core Operational Goal Relevant Features & Actions
1. Nurse Record daily patient vitals swiftly and accurately prior to physician rounds.
  • Room/Bed Directory: Visual overview of all 74 patient rooms with real-time vitals indicators (e.g., "Recorded Today" vs. "Pending").
  • Daily Temperature Logger: Rapid numerical vitals entry with automatic system timestamping.
  • Vitals History View: Chronological audit log of previous temperatures to check trends and prevent data-entry discrepancies.
2. Doctor Evaluate patient recovery trends, prescribe treatments, eliminate unproductive room entries, and identify cured patients.
  • Pre-Visit Vitals Check: Real-time status banner confirming if morning vitals are captured before entering patient rooms.
  • 3-Day Fever Tracker: 72-hour rolling history evaluating afebrile status against clinical discharge criteria.
  • Discharge Recommendation: One-click "Mark for Discharge" toggle that unlocks only when safety criteria are met, instantly alerting Admin.
  • Clinical Treatment Notes: Rapid entry of medication adjustments, symptoms, and clinical observations.
3. Admin Staff Manage 74-bed capacity, expedite room disinfection and discharge turnover, and monitor facility safety metrics.
  • Capacity Dashboard: Real-time 74-room capacity monitor (Occupied, Available, In Cleaning).
  • Discharge Processing Queue: Real-time alerts of doctor-cleared patients to initiate paperwork and bed turnover immediately.
  • Safety & Performance Analytics: Facility recovery tracking against the 85% success benchmark (15% expected mortality rate).

Q3: Logical Constraints & Validation Rules for Developers

To guarantee medical safety, operational efficiency, and data integrity, developers must implement the following four rule sets:

Domain Validation Logic & System Behavioral Rule
1. Temperature Logging Constraints
  • Multiple Entries: Nurses can log multiple entries per calendar day for acute monitoring.
  • Official Daily Reading: The system automatically timestamps each entry and designates the latest entry of the calendar day as the official metric for discharge calculations.
  • Physiological Bounds: Reject readings < 95.0°F (35.0°C) and > 108.0°F (42.2°C) with inline validation prompts.
  • Temporal Security: Timestamp is strictly system-generated. Future timestamps and backdated edits are blocked.
2. Doctor Visit Sequencing Rules
  • Pre-Visit Guard: If a physician opens a patient file where today_vitals_logged == false, display a prominent amber banner:
    ⚠️ Warning: Patient temperature has not been recorded today. Please coordinate with the nurse or record vitals first to avoid workflow delays and protect clinical safety.
  • Emergency Bypass: Doctors may override the warning with an emergency care note.
3. Discharge Eligibility Logic
  • Locked State: The "Mark for Discharge" button is disabled (disabled=true) by default.
  • 3-Day Afebrile Rule: System queries the backend log for the last 3 consecutive full calendar days (72h). Each day's maximum temperature must be strictly below 100.4°F (38.0°C).
  • Zero Gap Tolerance: If any of the 3 days lacks a recorded reading, the button remains locked.
4. Capacity & Operational Alerts
  • Full Capacity Alert: When active patient count reaches 74/74, the occupancy counter turns vivid red, and new admissions are queued.
  • Extended Stay Inefficiency Trigger (4-Hour Bottleneck Rule): When a doctor marks a patient "Ready for Discharge", an automated timer starts. If the bed is not vacated within 4 hours, an escalation banner flags on the Admin Dashboard to prevent stay inefficiencies.
